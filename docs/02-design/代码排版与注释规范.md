# 代码排版与注释规范

日期：2026-11-02。适用于项目自有 C# 代码，包括 Core、Gameplay、UI、编辑器工具、测试和控制台工具。

## 格式

- 四个空格缩进，UTF-8，LF 换行，文件末尾保留换行。
- 类型、方法、条件和循环的左花括号另起一行，左右花括号按所属层级对齐。
- if、else、for、foreach、while 等分支即使只有一条语句，也使用花括号；else if 仍作为连续条件书写。
- 一行只放一条操作语句，不把多个赋值、调用或判断挤在同一行。
- 方法和构造函数使用完整方法体。简单的只读属性可以保留简短表达式。
- 不同方法之间留一空行；长参数列表、长判断按层次换行。
- 保持现有命名空间和程序集边界。Unity 2022 的项目使用块级命名空间，不改成要求 C# 10 的文件作用域写法。

## 注释

函数前说明用途，关键逻辑块前说明处理目的、约束或原因。已有清楚的 XML 注释可以保留，不必再添加同义注释。

```csharp
// 首次读取时创建本架敌机的驾驶员，后续固定步复用观察与计时。
if (_gunner == null)
{
    _gunner = new GunnerPilot(grid, weapon, profile);
}
```

```csharp
// 把本步操作交给模拟，再把结果交给视图。
void FixedUpdate()
{
    var input = _input.ReadInput(Time.fixedDeltaTime);
    _simulation.Tick(input, Time.fixedDeltaTime);
}
```

不要给每个赋值都补“给某变量赋值”，也不要只写“处理逻辑”“执行功能”。注释应该说明这块代码在当前功能中的作用。测试方法已有清楚的场景名称时，重点保留测试步骤和特殊约束说明。

涉及单位、时钟、快照、资源所有权、旧机制兼容、初始化顺序的约束应写清楚；修改实现时同时更新相关注释。

## 整理代码的边界

排版不承担玩法修改。保留数值、字段名、序列化引用、计算次序与分支含义；不为了排版重命名 Inspector 字段或移动脚本及其 meta。

第三方包、Library、Temp、构建输出和自动生成文件不参加全项目排版。场景、prefab 与资产继续通过 Unity 序列化维护。

根目录 `.editorconfig` 保存共同规则；VS Code 的 C# 保存格式化已开启。编辑器格式化未必自动给无花括号分支补块，提交前仍要遵守上面的写法。
