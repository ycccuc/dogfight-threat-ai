## 一、一条原则、三条边界

第一阶段的目标里有一条容易被忽略的硬要求（立项书 ⑤）：

> **AI 自动对战测试框架，支持批量对战与胜率统计。**

要做到"批量对战"，必须能在**不渲染、不按真实时间、可复现**的条件下把一局跑完。
决定这件事的不是"用不用 MonoBehaviour"，而是下面三件事有没有被收进边界：

| 边界 | 做法 | 不这么做的后果 |
|------|------|----------------|
| **① 时间** | 全场景只有 `MatchLoop.Tick(dt)` 推进游戏；物理也由它手动 `Physics2D.Simulate(step)` | 逻辑散在几十个 `Update()` 里 → 无法快进、无法复现 |
| **② 输入** | 逻辑只读 `IPlaneInput`；玩家是 `KeyboardPlaneInput`，AI 是 `ScriptedPlaneInput` | AI 对战要另写一套游戏逻辑 |
| **③ 决策** | 行为树 / BFS / 伤害公式写在 `Dogfight.Ai`，用 asmdef 的 `noEngineReferences` **禁止**引用 UnityEngine | 换一条曲线就要开 Unity 试，没法单测 |

三条都守住之后，"AI 自动对战"就退化成一句话：**把飞机身上的输入实现换掉**。

### 为什么 `Ai` 要禁止引用 UnityEngine

代价是这一层拿不到 `Vector2` / `Mathf`，所以自己写了 `Vec2` / `MathUtil`（约 200 行，一次性的）。
收益是用**编译器**而不是靠自觉来保证边界：

- 单测不需要进 Play 模式，毫秒级跑完
- **可以脱离 Unity 编译**（本仓库用 `.scratch/aicheck/` 里的临时 .NET 工程验证过：0 错误 0 警告）
- 第三阶段的逻辑服务器（无头进程）能直接复用这一层，不用重写

> 如果你觉得某天这条边界碍事了：**先讨论，不要偷偷加 `using UnityEngine`** —— 那会让上面三条收益同时消失。

## 三、一帧是怎么走的

```
Update()  ──►  MatchLoop.Tick(Time.deltaTime)
                    │  按固定步长切片（1/60s，最多补 8 步）
                    ▼
              MatchLoop.StepOnce(step)
                    ├─ 1. 每架 PlaneAgent.Step(step)
                    │        ├ 从 IPlaneInput 读一帧输入
                    │        ├ FlightModel 算推力与目标角速度
                    │        └ 施加到 Rigidbody2D（只施力，不积分）
                    ├─ 2. Physics2D.Simulate(step)      ← 手动步进
                    ├─ 3. TickCount++ / ElapsedSeconds += step
                    └─ 4. 判定结束条件 → EndMatch() → MatchFinished 事件
```

**批量对战走的是同一条路**，只是把 `Time.deltaTime` 换成固定步长、循环调用 `StepOnce`，
并且不渲染。`Dogfight → 批量对战` 窗口跑的就是它。

### 关于物理的取舍

- 继续用 `Rigidbody2D`（立项书创新点 1 是"物理化飞行手感"，手感必须是真的物理）
- 但把 `Physics2D.simulationMode` 切成 `Script`，由 `MatchLoop` 决定何时步进
- **风险**：这个 API 的行为需要实机确认。所以有 `Dogfight → 验证 → 手动步进物理` 探针。
  若不可用，把 `MatchLoop` 的 `Manual Physics Step` 取消勾选即可退回 Unity 自动物理
  （代价：批量对战只能按真实帧率跑，慢，但功能不受影响）
- **已知限制**：PhysX 不保证跨运行完全确定性。所以批量对战用来统计**胜率趋势**是可靠的，
  但第三阶段若要"服务器权威 + 飞行回放"严格复现，可能要把运动学换成自研积分。
  **这是第三阶段的问题，现在不提前付成本。**

## 四、配置数据怎么走

```
编辑器里调（ScriptableObject）  ──Bake()──►  运行期纯数据（readonly struct）  ──►  Ai 层
   FlightProfileSO                            FlightSpec                        FlightModel
   WeaponConfigSO                             WeaponSpec                        DamageMath
```

**为什么不直接用 SO**：SO 属于 `UnityEngine`，`Ai` 层引用不到。
**为什么不用 JSON**：JSON 只能存字符串路径，丢失类型校验，也不能直接拖预制体/音效。
**JSON 用在哪**：跨进程消息协议（第二阶段）、存档与回放（第三阶段）—— 与这里不冲突。

**贴图同理**：代码里**不出现任何贴图路径或文件名**，一律通过 `SpriteBankSO` 用语义键取图
（`SpriteBankSO.Keys.PlayerPlane` 等）。这样"先用第三方素材、以后再换自己的"就只是改配置。

## 五、怎么跑

| 想做什么 | 怎么做 |
|----------|--------|
| 初始化新克隆的工程 | 打开 Unity → 菜单 `Dogfight → 项目初始化` |
| 检查配置有没有漏 | 菜单 `Dogfight → 检查项目配置` |
| 跑批量对战 | 菜单 `Dogfight → 批量对战`（输出 `tools/ai-benchmark/results/*.csv`） |
| 验证手动步进物理 | 进播放模式 → 菜单 `Dogfight → 验证 → 手动步进物理` |
| 跑单测 | `Window → General → Test Runner → EditMode → Run All` |
| 快速验证 Ai 层能编译 | `dotnet build tools/ai-compile-check/AiCompileCheck.csproj`（不需要 Unity，约 20 秒） |
