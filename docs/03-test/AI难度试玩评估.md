## 独立真实 Core 对照

子代理使用独立临时工程，只读链接真实 Core。共 432 组：72 组基准，360 组多初态复核。基准出生与 Unity 一致：玩家原点、敌机(4,-2.5)，两机均朝 +Y。实际场地为400×300，另有无限场地对照。起始时钟0/20/40/60，后续仍按真实时间成长，不能将90秒整轮结果理解为固定单一等级。

|---|---|

## 主要原因

高级侧翼候选围绕玩家的观察运动轴旋转，约每0.25秒重新选准备点；同时又要求接近准备点、速度几乎为零、严格对正才起手。玩家持续转向时，敌机不断追逐变化的准备位置，难以完成准备。

同一绕圈轨迹前20秒，三级1000帧里没有一帧进入准备点0.7范围；四级只有10帧进入，且没有一帧同时低速。三级/四级准备目标离散位置累计变化约260.8/278.5单位。这个累计值说明重选频繁，不是航点的物理连续速度，也不能仅凭它证明所有路线都无解；与逐帧准备失败、零起手和实机后段无伤共同支持上述判断。

0.8秒是预警长度，之后还有冲撞接近玩家的时间。因此典型静止起手的实际反应预算约1.1–1.3秒，并不等于HUD预警数字。这是当前样本的表现，不是全部朝向/速度/边界状态的保证。保留足够反应时间本身合理，优先问题是移动目标前的攻击机会丢失。

## 后续调整建议（本次未改参数）

1. 一轮进场短暂保持准备点，限制重选频率和变化幅度；只在目标明显离开该交会区域时放弃。
2. 无效侧翼占位超时后回退到可执行的截击；对固定绕圈预测下一处交会位置，提前等待玩家进入攻击区。
3. 保留0.8秒公开预警、锁向承诺和可躲窗口。成长先提升制造进攻机会的能力，不靠临时增速、追转或减少已公布反应时间。
4. 新增难度验收：移动目标前的有效起手频率、最长无效准备时间、重复两键策略与读预警策略的差异，以及各级0.3/0.6/0.9/1.1秒反应受击曲线。

本轮结论是“还需调平衡”，并非“已达到合适难度”。
